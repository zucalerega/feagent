# Whole-aircraft structural analysis: methods, parallel solvers, coupling, agent decomposition
NOTE: written from recalled literature, NOT live-verified this session (no web fetch run). Citations are well-known works; check versions/URLs before quoting. "[unverified]" marks items I am less sure of.

## 1. Industry practice
- Pipeline: external aero/inertial loads (CFD/panel, maneuver+gust, ground, landing, pressurization; CS-25/FAR-25 §25.301-25.571 limit & ultimate = 1.5x, fatigue/damage tolerance) -> Global FEM (GFEM): shells (skins, webs), beams/rods (stringers, spar caps, frames), RBE/spring fasteners, lumped masses; ~1e5-1e7 DOF; coarse (one element between stiffeners). Used for internal load distribution (stiffness-driven), NOT stress at details.
- Load extraction -> sizing: element/section loads (CBAR/CQUAD forces, interface loads via GPFORCE / MPCFORCE / SPCFORCE) feed hand/analytic margins of safety (stringer/panel buckling, fastener, lug) per Bruhn, "Analysis and Design of Flight Vehicles Structures"; Niu, "Airframe Stress Analysis and Sizing"; Megson, "Aircraft Structures for Engineering Students".
- Global-local / submodeling / zooming: (a) Submodel by cut-boundary displacement interpolation from global (Abaqus *SUBMODEL, Nastran "boundary-displacement" or enforced displacement via GRID). Valid if cut boundary is far (Saint-Venant) from the detail. (b) Load-based: apply extracted interface forces to local model with inertia relief/SPC. (c) Iterative/two-way global-local (Whitcomb 1991 NASA TM; Mao & Sun 1991; Gendron/Hinz; NASA Langley & Boeing/ Mark Rouse; "Global/local analysis of composite structures" Krueger/Knight, NASA/TM). NASA-STAR/GENOA-style multiscale. Two-way needed when local stiffness change (crack, cutout) redistributes load.
- Superelements / substructuring: static (Guyan) condensation K_red = Kbb - Kbi Kii^-1 Kib exact for statics (no approximation); exact load reduction f_red = fb - Kbi Kii^-1 fi; recovery u_i = Kii^-1(fi - Kib ub). Dynamics: Craig-Bampton (1968, AIAA J 6(7)) = boundary DOFs + fixed-interface normal modes; Hurty 1965; MacNeal hybrid (1971) free-interface. Nastran superelements (SESET, "SE" partitioned assembly, DMAP, Handbook for Linear Static Analysis / Reference Manual "Superelement Analysis"), Abaqus substructures (*SUBSTRUCTURE GENERATE, retained nodes, recovery run). Aerospace: ~fully automated via Nastran SOL 101/103 w/ SE; external SE (CSUPER/ASET) for supplier-delivered reduced models (Airbus/Boeing share condensed DMIG/OP4 matrices with partners; loads partner "Craig-Bampton reduced model" for coupled loads analysis, Gordon/Hanks, NASA-STD-5002 "Load Analyses of Spacecraft and Payloads").
- Verification norms: rigid-body modes (6 zero eigenvalues, free-free), unit-load/equilibrium check (sum reactions = applied), patch tests, mesh convergence (Roache GCI 1994/1998; ASME V&V 20; AIAA G-077), NAFEMS benchmarks, model-check checklist (free edges, duplicate nodes, MPC chains).

## 2. Domain decomposition / parallel solvers
| Method | Idea | Notes | Python/1-GPU usability |
|---|---|---|---|
| Static condensation / Schur complement (=superelement) | direct elimination of interior | exact; cost ~ sparse factor of Kii per part; trivially parallel across parts | scipy/cholmod; cuDSS (Schur complement feature exists in cuDSS >=0.4? [unverified]) |
| FETI / FETI-DP (Farhat-Roux 1991; Farhat-Lesoinne-Pierson 2000 "scalable dual-primal") | Lagrange multipliers on interfaces, PCG on dual, coarse problem for floating subdomains | designed for shells/plates w/ corner constraints; heavy to implement (null-space, projector) | no mature Python; FETI-DP in PETSc (PCBDDC covers BDDC; FETI-DP equivalent spectrum, Mandel-Dohrmann-Tezaur 2005) |
| BDDC (Dohrmann 2003) | primal; PETSc PCBDDC | needs MATIS format; works w/ petsc4py; CPU mainly | petsc4py yes, CPU; GPU limited |
| Schwarz (additive/ restricted, w/ coarse) | overlapping subdomain solves | PETSc PCASM/PCGASM; HPDDM; FreeFEM ffddm; Dolean-Jolivet-Nataf book 2015 (SIAM) | petsc4py |
| AMG | smoothed aggregation w/ rigid body modes (near-nullspace) essential for elasticity | hypre BoomerAMG (systems/ unknown-based, GPU CUDA backend works), PETSc GAMG (+ MatSetNearNullSpace; Kokkos/CUDA mats), AmgX (NVIDIA; aggregation AMG, pyamgx wrapper), Trilinos MueLu/ML | pyamgx (aging, small community), petsc4py w/ -mat_type aijcusparse -vec_type cuda; hypre via PETSc; cupy+ own PCG |
| GPU sparse direct | Cholesky/LDLT supernodal | cuDSS (NVIDIA 2024+; single GPU, multi-GPU (MG) and multi-node (MGMN) modes via NCCL/MPI; hybrid host-memory mode; LDL^T, Cholesky, LU); nvmath-python exposes `nvmath.sparse.advanced.DirectSolver` (cuDSS) [name unverified]; MUMPS GPU (partial, mostly dense front offload); STRUMPACK (GPU multifrontal + low-rank, ECP); SuperLU_DIST GPU; PETSc MatSolverType cudss? [recent versions add it; unverified] ; Pardiso/CHOLMOD GPU (SuiteSparse 7 supernodal GPU) | cuDSS is the practical one; ~1e6-1e7 DOF 3D fits in 80GB (3D fill is heavy: ~1e7 DOF tets could need >40GB factor) |
| Matrix-free / GPU FEM | JAX-FEM (Xue 2023 CPC), NVIDIA Warp.fem, MFEM-CUDA (partial assembly), deal.II MatrixFree, libCEED | PCG w/ Jacobi/Chebyshev/p-multigrid; shells/beam ill-conditioned -> poor w/o good preconditioner | JAX-FEM / Warp usable but would replace scikit-fem; high rewrite cost |
- 2020-26 GPU context: Ghysels et al STRUMPACK GPU; Hypre GPU (Yang et al); AmgX papers (Naumov 2015); GPU multigrid for elasticity (Adams-style PETSc GAMG + Kokkos, Mills et al "Toward performance-portable PETSc for GPU-based exascale systems" 2021); cuDSS release notes (2024-25). Takeaway: for <=~5e6 DOF shell/solid models a single GPU direct solve (cuDSS) is simplest and robust; iterative GPU AMG wins only when factor memory exceeds GPU or for >1e7 DOF 3D solids; thin-walled shells/beams are bad for CG+AMG (condition number ~ (L/t)^2-4) so direct is preferred.
- Key point: our single-part pipeline (scikit-fem + cuDSS) already is the "subdomain solver". The domain decomposition layer can be written in numpy as Schur complement on interface DOFs; no heavy FETI library required.

## 3. Interface coupling of independently meshed parts
Ranking by simplicity/verifiability:
1. Conforming shared interface (best): agents mesh along a gmsh-shared interface curve/surface with agreed node placement (gmsh fragment/ `occ.fragment` on whole assembly, or per-part meshes with prescribed 1D mesh sizes on shared edges, transfinite). Identical DOFs => assembly by node-id merge. Zero consistency error, patch-test passes. Constraint: parts not independent in meshing.
2. Rigid/interpolation MPC (RBE2 / RBE3): single master node (e.g., fastener/lug/bulkhead center) tied to a set of slave nodes. RBE2 stiffens (over-constrains) the interface; RBE3 weighted average doesn't add stiffness. Easy: add rows via penalty or elimination or Lagrange multiplier (KKT saddle; cuDSS LDL^T ok w/ indefinite / or penalty 1e3-1e6 x K diag). Verifiable by rigid-motion test and force sum. Standard for wing-fuselage attach, engine pylon, fasteners.
3. Node-to-surface tie (point-in-element projection, "tied contact" slave-nodes constrained to master-face shape functions): u_s - Σ N_i(ξ) u_mi = 0. Simple (scipy sparse C), but not energy-consistent (patch test fails when master mesh coarser than slave; stress oscillation); okay when slave mesh is the finer one (Abaqus default "surface-to-surface vs node-to-surface" guidance; Abaqus Analysis User's Manual, tie constraints).
4. Mortar (Bernardi-Maday-Patera 1994; Popp-Wohlmuth 2010 dual mortar; Puso 2004): integral weak constraint ∫ λ·(u1-u2) dΓ over non-matching interface, with dual Lagrange multipliers -> sparse D^-1 M elimination. Passes patch test, optimal convergence; implementation days-to-week: need segment intersection (2D lines easy; 3D polygon clipping hard). 2D/ line interfaces (beam-shell, shell edge) simpler. Nitsche variant also possible.
5. Bolted joint as springs/CBUSH-like: 3-6 DOF stiffness per fastener (Huth, Tate-Rosenfeld, Swift formulae for flexibility; Niu ch.) connecting two nodes; exactly what GFEMs do. Easy and verifiable by hand calcs; fastener loads are direct outputs. Gets dominant in joint-load results.
6. Shell-solid mixed: needs rotation->displacement coupling (RBE3/ shell-to-solid coupling in Abaqus); beware drilling DOF (scikit-fem Reissner-Mindlin/ Kirchhoff support limited -> check what our solver offers: if only 3D solids with 3 DOF/node, beam/shell idealizations and rotations are N/A; ties then only translate => use solid/ thickened mesh).
- Best-in-setting recommendation: (1) conforming gmsh assembly where parts are cheap, plus (2)+(5) for lugs/fasteners; (3) node-to-surface with finer slave as fallback; defer mortar. Always check: rigid body translation/rotation of tied pair yields zero interface forces; interface force equilibrium; stress jump across tie small after refinement.

## 4. Agent decomposition
Level-0 plan (airplane agent / architect): defines coordinate system, units, interface table (interface ID, location, type RBE/spring/conforming, DOF set, shared node coordinates/sizes), load-case table (maneuver n, gust, landing, pressurization; applied to which interface/panel), material table, mass breakdown. => "interface control document" (ICD) JSON. This is the key artifact; makes parts parallel.
Component agents (N parallel; CPU meshing, GPU solve): 
 - mesh+verify part (existing harness gates), honor interface mesh sizes from ICD;
 - produce reduced model: boundary DOF set B = interface nodes (+ master nodes of RBE); compute Schur complement S = Kbb - Kbi Kii^-1 Kib (dense nb x nb; nb ~1e2-1e4) via cuDSS multi-RHS solve (nb RHS) or single factor + triangular solves, and condensed load vector g. Artifact: npz {B node ids+coords, S, g, M reduced optional, Kii factor NOT shipped, recovery recipe: mesh, material hashes, BC file}. Check: S symmetric PSD, 6 zero modes for unconstrained part (rank nb-6 after unconstrained), S @ rigid-body-vectors ≈ 0.
 - local strength post-processing is deferred to recovery stage.
Integration agent (serial core, light): assemble global interface system Σ T_p^T S_p T_p u_B = Σ T_p^T g_p (+ spring/RBE rows + SPC/inertia relief for free flight with 1g/ n g balanced loading, since aircraft is free: use inertia relief or apply reaction at CG with self-equilibrated loads), solve (dense/sparse Cholesky, nb_total ~1e4-1e5 fine on GPU dense or cuDSS), output u_B per interface + interface forces F_B = S u_B - g. Then dispatch u_B (displacement-based) or F_B (force-based) back to component agents.
 - Recovery (parallel again): each part reruns its own solve with prescribed boundary displacements u_B (exact, since condensation is exact for statics) -> full stress fields -> margins/hot spots. Equivalent to global solve to solver tolerance — "physically correct" without a monolithic model.
Verification agent: (a) rigid-body / equilibrium: Σ applied + reactions = 0 per part and global (force and moment about CG); (b) monolithic reference on a small assembled test (a 2-3 part toy) compare u at checkpoints to Schur-assembled result (should match to ~1e-8 for conforming); (c) global-local consistency: energy sum Σ ½ u_B^T S u_B + interior energy = ½ f^T u; compare coarse-global and fine-local displacement at interface (relative jump < tol, else trigger refinement); (d) GCI over 3 mesh levels per part (Roache) for peak stress / tip deflection, with interface mesh coupled; (e) unit checks vs analytic beam/plate (cantilever wing box tip deflection PL^3/3EI w/ shear correction); (f) interface continuity of traction for nonconforming ties.
Data flowing: ICD(json) -> mesh+interface node sets (.msh/.npz) -> S_p,g_p (npz, hashed) -> global u_B,F_B -> per-part recovery results (vtk/npz + margins json) -> verification report. Everything content-addressable to avoid stale reduced models.
Parallelism: parallel — part meshing (CPU), condensation (GPU; batch over parts; one cuDSS handle per stream; multi-GPU by assigning parts to devices; memory-bound so run 1-2 per GPU 80GB), recovery solves, GCI refinement ladders, load-case sweeps (factor once, back-solve many RHS — big win: all load cases are RHS only). Serial — ICD freeze, interface-mesh compatibility check, global interface solve, final verification. Iteration (nonlinear/ two-way) if local stiffness differs: re-run condensation for changed part only (others cached) => incremental redesign.

## Ranking (correctness / implementability in days with scikit-fem+gmsh+cuDSS / GPU benefit)
1. Static condensation (Schur superelement) w/ conforming or RBE/spring interfaces, then displacement-recovery: correctness 5 (exact for linear statics), impl 4 (~3-5 days; main work: boundary-DOF bookkeeping, multi-RHS cuDSS, free-body/inertia relief), GPU 4 (many RHS, big factorizations; dense S small).
2. Monolithic global solve of the conformingly merged mesh with cuDSS (as validation oracle and for <~5e6 DOF): correctness 5, impl 5 (days: 1), GPU 4; does not scale beyond GPU memory but is the easy test baseline. Use for verification of #1.
3. Global-local submodeling (coarse whole-aircraft model w/ beam/rod + RBE, then local fine solid model driven by cut-boundary displacements): correctness 3-4 (one-way; needs distance from boundary & stiffness similarity), impl 4, GPU 3. It's the industry default for sizing; needs a coarse global idealization that scikit-fem solids may lack (no shell/beam?? check).
4. Mortar/ node-to-surface ties for nonconforming parts: correctness 3 (n2s) / 5 (mortar), impl 3 / 1-2, GPU neutral.
5. Iterative DD (FETI-DP/BDDC via petsc4py): correctness 5, impl 1-2 (weeks, learning curve, shells), GPU 2-3 — only for > single-GPU scale.
6. GPU AMG (AmgX/hypre/GAMG) on full monolithic: correctness 5 if near-nullspace right, impl 2, GPU 4 at >1e7 DOF 3D solids; poor for thin shells.
7. Matrix-free JAX/Warp rewrite: impl 1, GPU 5; not recommended now.
8. Craig-Bampton dynamic reduction: only if modal/flutter/coupled-loads needed; extension of #1 (add fixed-interface modes via LOBPCG/cuSOLVER eigsh).

## Caveats / what to check next
- Confirm cuDSS Python API names and Schur-complement feature set and MGMN status in current docs (docs.nvidia.com/cuda/cudss).
- Our solver's element types (solid only? shells?) decide whether RBE/rotation coupling is meaningful; with 3-DOF solids use conforming interfaces or translational RBE3-like ties and spring fasteners (no moment transfer).
- Free-flight aircraft: singular K; use inertia relief (Nastran PARAM,INREL; Abaqus *INERTIA RELIEF) or SUPORT at CG / weak springs — verify net load equilibrated.
- Precision: use fp64 for Schur and Kii solves; condensation of stiff parts with soft interfaces loses digits; report cond(S).
