# NAFEMS LE11 (axisymmetric): error maps

Per element: RMS over the reference integration points inside it (9981 points in all) of the relative von Mises error |vm - vm_ref| / max(vm_ref, 0.2 median(vm_ref)) (the run report's pointwise error, ace/run_report.py _field). Log colour scale clipped to 0.003-0.3, identical on the three panels; mesh edges overlaid. Same meshes and numbers as the combined figure. The automesher's error is largest at the two kinks G and D; both agents shrink it there to a few small elements. The trained agent's larger background elements leave somewhat more error away from the kinks than the early agent's, with 648 instead of 812 DOFs and the same field error (0.71 % vs 0.71 %). NAFEMS LE11 axisymmetric (hollow cylinder / taper / sphere, steel, E = 210 GPa, nu = 0.3, alpha = 2.3e-4 /degC, temperature T = r + z, i.e. x + y in the section; no mechanical load; stresses in MPa), run `ace_runs/deep1`. Field error = relative energy-norm error of the whole stress field vs the fine reference (`ace/field_refs/nafems_le11_axisym.npz`, 53,412 DOFs; a coarser reference solve differs from it by 0.16 %, so the reference's own error is below that). Each mesh was rebuilt from its request and re-solved with the fixed skfem solver as the scorer does; the re-solved field errors and DOFs match the stored ones (`data/nafems_le11_axisym/panels.json`). Excluded: g0-nafems_le11_axisym-a0, g0-nafems_le11_axisym-a4, g0-nafems_le11_axisym-a5, g0-nafems_le11_axisym-a7 (generation 0), because they applied the temperature sqrt(x**2+y**2)+y instead of the problem's x + y, a setup mistake rather than meshing (field error 26.78 %-26.80 %).
